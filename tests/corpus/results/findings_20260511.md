## Proposed Fixes

Based on the pattern analysis above, the following improvements are suggested:

1. **Bold/italic surviving**: Ensure `strip_inline` is called on every non-code, non-blank line. Verify code fence detection is not leaving too many lines marked as `in_code=True`.

1. **Files heavy in code fences**: Code fences are intentionally kept verbatim because converting them to `=== BLOCK` syntax would ADD tokens. This is expected behaviour -- no fix needed. Files with many large code blocks will naturally show lower savings.

1. **Plain-prose files losing tokens (8 files)**: These files contain no strippable Markdown decoration. The only change is adding the `@slim: 1.0` header (~9 tokens overhead). Root cause: the corpus generator needs to produce files with richer Markdown formatting (bold, links, badges, tables, YAML frontmatter) for the converter to show meaningful savings. Alternatively, consider making the `@slim: 1.0` header optional when the input has no YAML frontmatter.
